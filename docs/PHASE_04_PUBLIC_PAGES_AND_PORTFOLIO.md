# Phase 4: Public Pages and Project Portfolio

## Objective

Implement the internal public-facing pages and a portfolio that presents
CRL's documented experience accurately.

## Pages

### Company

Include company overview, history, vision, mission, client philosophy,
technical expertise and company credentials supported by the profile.

### Services

Create sections or detail pages for: - Architecture. - Construction. -
Building Services. - Project Management.

Use the source profile for descriptions. Do not add unsupported service
claims.

### Projects

Create a filterable portfolio with supported categories: -
Residential. - Commercial and Industrial. - Religious. - Educational. -
Healthcare. - Hospitality. - Infrastructure and Roads. - Institutional.

### Project detail

Display: - Project title. - Category. - Location. - Documented year or
date range. - Documented status. - CRL's documented role. - Supported
description. - Main photograph and gallery.

Preserve completed, ongoing and stalled distinctions. If a status is not
known, do not infer it.

### Team

Include the core team and affiliate consultants documented in the
profile. Use verified qualifications and biographies. Do not invent
missing photographs or details.

### Contact

Display the verified office address, telephone numbers and primary
email. Implement the actual enquiry workflow in Phase 6.

## Portfolio design

Use varied image proportions, strong editorial layouts, category
filtering and accessible image viewing. Avoid an ordinary grid of
identical cards.

## Deliverables

-   Company page.
-   Services page.
-   Projects index.
-   Project detail template.
-   Team page.
-   Contact page structure.
-   Responsive and navigation tests.
