# Phase 1: Audit and Discovery

## Objective

Understand the current CRL website, Laravel repository, installed
dependencies, existing content and available media before making
structural changes.

## Tasks

1.  Inspect the repository structure and identify the Laravel version,
    PHP version, Filament version, Livewire version, database, Vite
    setup and frontend dependencies.
2.  Inspect the current website at https://qtribe.com.ng/dev/crl/ and
    document existing pages, working features, visual issues and
    content.
3.  Inspect the benchmark websites:
    -   https://fmaarchitects.com/
    -   https://schmidtarchitects.co/
4.  Review all 36 pages of the supplied CRL company profile, including
    page images and project photographs.
5.  Inventory the existing CRL logo, photographs, fonts, icons and other
    assets.
6.  Identify which existing images can be mapped to which projects. Do
    not assume an image belongs to a project unless the source supports
    that relationship.
7.  Identify missing or unclear information that needs client
    confirmation.
8.  Identify existing routes, models, migrations, controllers, Blade
    views, Livewire components and Filament resources.
9.  Identify risks to existing functionality and data.

## Deliverables

Create an audit report containing: - Existing application and dependency
summary. - Existing page and functionality inventory. - Asset
inventory. - Company profile content inventory. - Benchmark design
observations. - Recommended website information architecture. -
Recommended Laravel and Filament implementation approach. - Data model
proposal. - Risks and questions requiring client confirmation. -
Phase-by-phase implementation plan.

## Restrictions

Do not delete assets, replace the logo, run destructive migrations,
upgrade major dependencies or deploy anything during this phase.

## Approval gate

Present the audit and proposed implementation plan. Wait for approval
before beginning broad implementation.
